Admin Settings Requirement

THERASSISTANT must include a complete Admin Settings module because the RCM workflow depends on configurable organization, payer, EDI, provider, billing, posting, security, and audit rules. Admin settings are not cosmetic. They are operational controls for claim generation, eligibility, ERA matching, payment posting, reconciliation, reporting, and compliance.

Required Admin Settings Areas
1. Organization Settings

Admin must manage each billing organization:

Legal organization name
DBA, if applicable
TIN / EIN
Type 2 NPI
Phone
Billing address
Pay-to address, if different
Contact email
Active/inactive status
Default billing provider identity
Default rendering provider rule
Organization-specific Availity submitter ID
Organization-specific SFTP mailbox configuration
Environment: QA or Production

For MVP, organization settings must support at least:

Conscious Counseling PLLC
Kindly Kiera LLC

The system must support organization-level claim generation and not assume every claim belongs to the same billing entity.

2. Provider / Clinician Settings

Admin must manage clinicians and provider identities:

Clinician name
Credentials
Individual NPI
Email
Parent organization
Active/inactive status
Internal service clinician
EDI rendering clinician
Default rendering provider assignment
Provider taxonomy, if needed later
Sensitive credentialing fields stored securely only if required

The system must distinguish between the clinician attached to the appointment/session internally and the rendering provider emitted on the 837P.

5. Charge / Claim Settings

Admin must control claim readiness and charge behavior:

Required fields for charge release

Allowed charge statuses

Default place of service
Default diagnosis behavior
CPT/HCPCS validation rules

Batch grouping must use:

Organization
Payer
Environment

Generated claims must persist to the same canonical claim tables used by claim search, ERA matching, AR, patient profile, payment posting, and reports.

6. ERA / Posting Settings

Admin must control ERA review and posting behavior:

Auto-match rules
Manual-match requirements
ERA review statuses
Required fields before posting
Whether 835 files auto-post or require review
Adjustment posting rules
Contractual write-off rules
Patient responsibility transfer rules
Denial creation rules
Partial payment behavior
Duplicate payment detection
Overpayment handling
Reversal/correction behavior

For MVP:

835 ERA files may be parsed and matched automatically.
835 ERA files must not auto-post financially until reviewed/approved by a user.
Posting must create real payment, adjustment, service-line posting, and balance records.
If posting is blocked, the UI must state exactly what is missing.
7. Patient Payment / Credit / Refund Settings

Admin must control:

Accepted patient payment methods
Default payment location/source
Overpayment handling
Credit creation rules
Refund approval rules
Refund status workflow
Balance allocation order
Whether unapplied credits are allowed
Whether patient payments can be posted without an open balance
Reconciliation behavior for patient payments

Patient payments must apply to canonical patient balance records and appear in payment history and billing reports.

8. Denial / AR Settings

Admin must manage:

Denial reason categories
CARC/RARC mapping
Write-off categories
AR follow-up statuses
No-response tracking thresholds
Follow-up due date rules
Appeal/reconsideration/corrected claim categories
Credentialing/contract denial handling
Workqueue assignment rules

Credentialing/contract-related denials should follow THERASSISTANT policy and not be worked unless explicitly configured otherwise.

9. Billing Navigation Settings

Admin must control or at least validate active billing navigation:

Each billing nav item must point to an existing route.
Legacy routes must redirect or be removed.
/billing/payments/posted must either exist or every reference to it must be updated.
Every billing page must have a defined role in the workflow.
Navigation must not expose dead pages, duplicate pages, or disconnected legacy modules.
